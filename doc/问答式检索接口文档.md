# QueryController 问答式检索接口文档

## 1. 范围说明

本文档仅覆盖 `QueryController` 中两个问答式检索流式输出接口：

- `POST /text_search/questionStream`
- `POST /text_search/summary_questionStream`

两者都返回 `text/event-stream;charset=UTF-8`，通过 SSE 持续输出“检索 + 问答”结果。

## 2. 接口概览

| 接口 | 方法 | 说明 |
|---|---|---|
| `/text_search/questionStream` | POST | 标准问答式检索。先从多库召回段落，再把召回结果交给大模型流式回答。 |
| `/text_search/summary_questionStream` | POST | 摘要问答式检索。先做摘要向量检索并推送匹配结果，再把匹配摘要作为上下文交给大模型流式回答。 |

## 3. 通用约定

### 3.1 请求头

```http
Content-Type: application/json
Accept: text/event-stream
```

### 3.2 响应类型

```http
Content-Type: text/event-stream;charset=UTF-8
```

### 3.3 SSE 输出约定

Java 侧使用 `SseEmitterUTF8.send(...)` 输出标准 SSE `data:` 行。

- 普通流式事件：`data: <内容>`
- 错误事件：`event: error` + `data: {"message":"..."}`
- `summary_questionStream` 会先由 Java 服务端主动补发一条 `query_result` 事件
- `reason`、`answer`、`cite`、`[START]`、`[DONE]` 等内容属于算法侧流式输出，Java 侧按收到的内容透传给前端

## 4. 标准问答式检索

### 4.1 接口定义

- URL：`POST /text_search/questionStream`
- 说明：输入用户问题，先进行检索召回，再进行问答式流式输出

### 4.2 请求参数

请求体类型：`QuestionParam`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | String | 否 | 会话 ID，原样透传给算法侧流式事件。 |
| `question` | String | 是 | 用户问题。 |
| `mode` | String | 否 | 模型模式，例如 `deepseek`。 |
| `history` | Array | 否 | 历史对话。 |
| `context` | Object | 否 | 额外上下文约束。 |

`history` 元素结构：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `role` | String | 否 | 角色，如 `user`、`assistant`。 |
| `content` | String | 否 | 对话内容。 |

`context.book` 结构：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `title` | String | 否 | 书名。 |
| `author` | String | 否 | 作者。 |
| `library` | String | 否 | 馆藏/库来源。 |
| `four-fold` | String | 否 | 四部分类。 |
| `type` | String | 否 | 书籍类型。 |
| `content` | String | 否 | 书籍补充内容。 |

`context.chapter` 结构：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `title` | String | 否 | 章节标题。 |
| `content` | String | 否 | 章节内容。 |

### 4.4 处理流程

1. 对 `question` 进行向量化和分词，生成 `Query`。
2. 并发从 3 个库召回数据：
3. `FAMOUS_ANCIENT_BOOK`
4. `ANCIENT_BOOK`
5. `GENERAL_DOCUMENT`
6. 合并召回结果后，交给算法服务进行流式问答。
7. Java 服务本身不在流中主动插入检索结果明细，只负责透传算法服务返回的流式事件。

### 4.5 SSE 事件说明

该接口常见事件如下：

| 事件形态 | 来源 | 说明 |
|---|---|---|
| `data: [START]` | 算法侧 | 表示本轮流式输出开始。 |
| `data: {"session_id":"...","type":"reason","value":"..."}` | 算法侧 | 推理过程片段。 |
| `data: {"session_id":"...","type":"answer","value":"..."}` | 算法侧 | 正文答案片段。 |
| `data: {"session_id":"...","type":"cite","value":{...}}` | 算法侧 | 引用信息。 |
| `data: [DONE]` | 算法侧 | 表示本轮流式输出结束。 |
| `event: error` + `data: {"message":"..."}` | Java 侧 | Java 服务内部异常或超时。 |

### 4.7 错误输出示例

算法侧业务校验失败时，前端可能收到类似内容：

```text
data: [DONE]

data: {"sessionId":"127a85ca-5de5-4c8d-8438-7c2764a334ca","type":"error","value":"检索必要条件不能为空"}

data: [START]
```

说明：

- 该类内容不是 Java 控制器主动组装的固定格式，而是算法侧返回后由 Java 透传
- 前端接入时应按实际 `data:` 内容解析，不应假设只有 `reason` 和 `answer`

## 5. 摘要问答式检索

### 5.1 接口定义

- URL：`POST /text_search/summary_questionStream`
- 说明：先根据摘要内容检索匹配摘要，再基于匹配结果进行流式问答

### 5.2 请求参数

请求体类型：`SummaryQuestionParam`

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `session_id` | String | 否 | 无 | 会话 ID。 |
| `summary` | String | 是 | 无 | 用户输入的摘要或问题主体。 |
| `fourFold` | String | 否 | 无 | 四部分类，精确过滤。 |
| `title` | String | 否 | 无 | 书名，精确过滤。 |
| `author` | String | 否 | 无 | 作者，精确过滤。 |
| `threshold` | Float | 否 | `0.55` | 相似度阈值。 |
| `topN` | Integer | 否 | `5` | 召回并喂给模型的最大条数。 |
| `mode` | String | 否 | 无 | 模型模式，例如 `deepseek`。 |
| `history` | Array | 否 | 无 | 历史对话。 |

### 5.3 请求示例

```json
{
  "session_id": "JIdejgad",
  "summary": "一部记录古籍目录的文献",
  "fourFold": "史部",
  "title": "楝亭书目",
  "author": "[清] 曹寅 藏并编",
  "threshold": 0.55,
  "topN": 5,
  "mode": "deepseek",
  "history": [
    {
      "role": "user",
      "content": "你是谁？"
    },
    {
      "role": "assistant",
      "content": "我是古汉语大模型"
    }
  ]
}
```

### 5.4 处理流程

1. 对 `summary` 做向量化。
2. 仅查询摘要库的 Milvus 数据。
3. 按 `threshold` 做阈值过滤。
4. 如果传了 `fourFold`、`title`、`author`，则继续做精确过滤。
5. 按相似度倒序排序，截取 `topN`。
6. Java 服务先发送一条 `type=query_result` 的检索结果事件。
7. 再把命中的摘要内容转成问答上下文，继续调用算法服务流式输出 `reason`、`answer`、`cite` 等事件。

### 5.5 `query_result` 事件结构

该接口与 `questionStream` 的主要区别，是流开始阶段会多一条检索结果事件：

```json
{
  "session_id": "JIdejgad",
  "type": "query_result",
  "value": [
    {
      "bookId": 1006408,
      "fourFold": "史部",
      "title": "楝亭書目",
      "author": "[清] 曹寅 藏并编",
      "score": 0.83
    }
  ]
}
```

`value` 中每条记录字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `bookId` | Long | 书籍 ID |
| `fourFold` | String | 四部分类 |
| `title` | String | 书名 |
| `author` | String | 作者 |
| `score` | Float | 相似度得分 |

注意：

- `query_result` 只返回匹配记录摘要，不返回摘要正文
- 摘要正文仅在服务端内部作为大模型上下文使用

## 6. 错误与超时说明

### 6.1 Java 服务内部异常

Java 服务捕获异常后，会发送：

```text
event: error
data: {"message":"系统内部错误"}
```

### 6.2 SSE 超时

SSE 超时时间为 `600000ms`。超时后会发送：

```text
event: error
data: {"message":"请求超时"}
```

### 6.3 前端接入建议

- 既要处理 `event: error`，也要处理 `data:` 行中的业务错误对象
- 不要把流式事件类型写死为只有 `reason`、`answer`
- 对 `query_result`、`cite`、`type=error`、`[START]`、`[DONE]` 都应兼容
