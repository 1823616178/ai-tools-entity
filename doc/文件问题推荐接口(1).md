# 文件问题推荐接口文档

## 接口概述

- **接口名称**: `http://ip:port/document_recommended_questions`
- **调用方式**: POST
- **Content-Type**: `application/json`
- **接口描述**: 当用户上传一个或多个文件且输入框为空时，应用端将文件解析为纯文本后调用本接口，服务基于文件内容生成推荐问题。接口支持流式和非流式两种输出模式，内部统一使用流式生成链路；当 `stream=false` 时，服务端消费完整流式结果后返回 JSON。

## 请求参数

| 参数名 | 参数类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| documents | array[object] | 是 | 文件文本列表，长度 1-50 | 见示例 |
| documents[].file_name | string | 否 | 文件名，用于多文件上下文标识；为空时服务端使用 `文件N` | `档案1.pdf` |
| documents[].text | string | 是 | 应用端解析后的纯文本，不能为空字符串 | `故宫博物院...` |
| question_count | int | 否 | 期望生成的推荐问题数量，默认值由 `document_recommended_questions.question_count` 配置，范围 1-10 | `3` |
| stream | bool | 否 | 是否使用 SSE 流式输出，默认 `false` | `true` |

## 非流式响应

当 `stream=false` 或未传时，返回 JSON：

```json
{
  "code": 200,
  "message": "success",
  "recommended_questions": [
    "故宫在明清时期承担什么功能？",
    "故宫的占地面积和建筑规模有多大？",
    "这些文件分别介绍了故宫的哪些方面？"
  ]
}
```

## 流式响应

当 `stream=true` 时，响应类型为 `text/event-stream`。`answer` 事件返回模型原始文本增量，`result` 事件返回解析后的推荐问题数组：

```text
data: [START]

data: {"type":"answer","value":"1. 故宫在明清时期"}

data: {"type":"answer","value":"承担什么功能？"}

data: {"type":"result","value":{"code":200,"message":"success","recommended_questions":["故宫在明清时期承担什么功能？"]}}

data: [DONE]
```

可能出现的事件类型：

| type | 说明 |
|---|---|
| answer | 模型正文增量 |
| reason | 模型思维增量，仅在启用思维链且模型返回时出现 |
| result | 最终结构化结果 |
| error | 流式生成中的错误 |

参数错误发生在生成前，仍返回普通 JSON 400。

## 请求示例

```json
{
  "documents": [
    {
      "file_name": "故宫简介.txt",
      "text": "故宫博物院，旧称紫禁城，位于北京市中心，是中国明清两代的皇家宫殿。"
    },
    {
      "file_name": "建筑规模.txt",
      "text": "故宫占地面积72万平方米，建筑面积约15万平方米，共有大小宫殿七十余座。"
    }
  ],
  "question_count": 3,
  "stream": false
}
```

## 异常响应示例

```json
{
  "code": 400,
  "message": "参数错误：documents 不能为空"
}
```

```json
{
  "code": 400,
  "message": "参数错误：stream 须为布尔值"
}
```

## 注意事项

1. 本接口不接收二进制文件，只接收应用端解析后的纯文本。
2. 多文件会按传入顺序拼接，并在每段文本前加入文件序号和文件名。
3. 输入内容统一按 `llm.max_input_tokens` 做 token 预算，服务会保留固定提示词和输出要求，只截断文件正文。
4. 推荐问题只基于传入文件文本生成，不应引入外部信息。
